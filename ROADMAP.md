# Roadmap

Technical work planned beyond the campaign document structure itself.

## 1. & 2. Foundry VTT module (sync + logistics, one module)

These turned out to be one module, not two — `foundry/blank-inheritance/`, decided when actually designing it. It ships the campaign JSON and the module code together (one WinSCP push deploys both), syncs `/data` into Foundry documents (Scenes, Actors, JournalEntries, Playlists), supports pulling GM edits back down, and runs session logistics (time tracking, a director's panel for cueing scenes/transitions/music).

- **Design**: [design/foundry-module-design.md](design/foundry-module-design.md) — architecture and decisions.
- **Reference**: [design/foundry-technical-reference.md](design/foundry-technical-reference.md) — the exact Foundry v14 / sf2e APIs the design relies on, verified against local source trees.
- **Status**: designed, directory skeleton exists (`foundry/blank-inheritance/`), no generation/sync code written yet. See the design doc's §9 for the staged build order — core push pipeline first, director's panel and cold-open sequence last.

Run manually, on demand. Not automatic, not LLM-mediated for the actual document mutation — that's the whole reason this project stores everything as JSON.

## 3. Encounter simulator

A simple simulator for Starfinder 2E encounters — run a simulated fight, examine the results, and use that to tune Claimant builds and Frame ability-band assignments. The schemas (`encounter.schema.json`, `challenge.schema.json`, `subsystem.schema.json`, `reference/tables/`) already carry the numbers this would need.

**Status: a first real slice exists.** `tools/battle-simulator/` — a legality-enforcing engine (real dice via a seeded PRNG, a rules layer that rejects illegal moves rather than trusting callers not to propose them) scoped specifically to the scale-and-chassis ruleset (design/scale-and-chassis.md), not general SF2E. Built 2026-08-22 to demonstrate that ruleset before committing to it, with its output viewable as a scrubbable Artifact. Adversarially tested by five independent agents; see `test/battle-simulator/` for the resulting regression suite. What remains long-term/unbuilt: personnel-scale (ground-role) simulation, a general (non-scale-and-chassis-specific) SF2E mode, and folding `challenge.schema.json`/`subsystem.schema.json` data in directly rather than hand-authored scenario files.

- **Combat AI roadmap (2026-09-02)**: the personnel-scale AI's own road from today's one-move-ahead evaluator to Monte Carlo Tree Search and learned play is tracked as GitHub issues — epic [#3](https://github.com/Garsondee/blank-inheritance/issues/3), milestone 1, 20 ordered issues. See design/scale-and-chassis.md §54–§56 for the measurements that motivated it.

## 4. Real-data campaign map

The campaign map, built from real OpenStreetMap + GSI Japan DEM data (real Kobe, rotated, renamed, fictionalised) rather than generated from a seed — a real city plus terrain and buildings, styled and rendered as the game's world map and eventual VTT battle-map backdrop, editable after the fact via an append-only operation log so campaign events (construction, damage, reclamation) never require a from-scratch re-render.

- **Design**: [design/map-generation.md](design/map-generation.md) — pipeline, the "grammar" that keeps synthesised edits looking native to the imported city, the operation-log format, rendering approach.
- **Provenance**: `ideas/entries/procedural-city-map-generator.json` — decision history, including the 2026-08-24 pivot away from this entry's original fully-procedural plan toward real data (`tools/map-generator/`, the Node/JS tool that idea shipped, keeps a narrower role — amplification and offshore bathymetry — and is not superseded as a tool).
- **Status**: structural core, the operation log, and a real progress-reporting CLI are all built and tested (`tools/city-map/`, Python — parsing, multipolygon relation reconstruction, sea/land classification, hillshade, contours, tiled rendering, road-AND-rail-graph-aware demolition, parametric-template construction with routed access roads and terrain benching; 400+ tests in `test/city-map/`, run separately from `npm test`). The vertical slice this milestone was scoped around is done: Kobe Airport reclaimed by the sea and a mech-bunker template constructed nearby, both driven by a real operation log (`data/map/operations/kurose.json`) and rendered end-to-end via `python render.py --mode full --ops ...`. Since then (2026-08-24): demolish's graph-cascade pruning was generalized from roads-only to a second, independent pass over a `rail_graph` (a dangling railway bridge over open water was slipping through, since railways had no graph representation at all to prune against); rivers now draw above contours instead of under them, and taper at their sources and widen at confluences (`citymap/rivers.py`, Shreve stream magnitude); Port Island and Rokko Island were both removed the same way as Kobe Airport, clearing the site for sci-fi sea forts; and offshore construction's phase (a) — anchor-in-sea detection, land reclamation as the literal inverse of `returnToSea`, flat freeboard elevation instead of slope-benching — is built directly into `construct.py` and proven against real data (see `ideas/entries/offshore-construction.json`'s resolution). A second Sentinel Tower template shipped and three real sites were placed in the mountain valley using an auto-sited, dry-run-verified search (the same method now codified in `citymap/editor/siting.py`, see below). Also since then: `render.py`'s hillshade and building-cast-shadow layers were fixed to actually darken roads and other buildings, not just bare ground (buildings previously drew last and fully opaque, silently erasing any shadow that fell on them); a real bug was found and fixed where `apply_demolish` silently dropped every terrain edit recorded by an earlier construct op; and the op-log replay itself is now cached (`citymap/ops/replay_cache.py`, content-hashed on the ops list, reusing `save_world`/`load_world` unchanged) — a render with an unchanged op log skips the 500s+ replay entirely. `tools/city-map/editor/` is a local Leaflet-based map editor (`python tools/city-map/editor/server.py`) for drawing new construction sites (land or sea), flagging existing buildings for removal, sketching road connections, and triggering renders with live SSE progress, instead of the AI guessing sites from a screenshot that gets lost to context compaction. Not yet built: causeway routing (offshore construct places new land and a building but has no access road at all yet — phases b–d of `ideas/entries/offshore-construction.json`), turning a road sketch from the editor into a real routed road (the editor captures the sketch; feeding it through `ops/router.py` is still a manual step), the grammar module (road classes use fixed defaults, not the imported city's own measured statistics), and the page-furniture render pass (labels, cartouche, compass rose, paper texture).
