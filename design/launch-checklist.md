# Launch checklist: what has to be true before the campaign starts

*Written 2026-10-01 at Ingram's request (D055: "the checklist (which you should now produce) of things to do before launching the campaign"). A working list. Claude keeps it current, and every status says where it comes from and when it was checked, so it cannot quietly go stale. It does not replace GitHub epic #140, which tracks the same ground from the engineering side and is partly out of date (its body was last audited 2026-09-20); this is the plain list to work from, and #140 links here.*

Words here are the repo's own: a **Chapter** is a level, an **Episode** is a chunk of authored content, a **Session** is a real evening at the table. "Launch" is two gates, because induction is done by each player on their own, at any time before the adventure starts (`design/induction.md`), and Episode One is the first thing played together.

- **Gate A: induction opens.** Each of the six can make a character on their own. Section A. Item A-10 is the same gate reached by post.
- **Gate B: Episode One can be played.** The first Session. Section B.
- **Section C: the Discord server.** New 2026-10-01. Optional, not a gate.
- **Section D: not gates.** Known gaps that do not hold launch back.

`[ ]` not done · `[~]` partly · `[x]` done and checked. **You** means only Ingram can do it (a read, a grade, a choice, her own accounts). **Claude** means Claude can do it once told. **Both** means it needs the two of us.

**How this was checked, 2026-10-01.** A read-only pass over the repo and the Sign-Off board, the offline deploy status, the open GitHub issues, and the code paths named below. **Not checked, because it cannot be seen from here:** what is actually in the live Foundry world (use Admin, then State: it lists the roster, any lent test party and the pawns), the player accounts, whether the live server matches the last deploy record, and whether the audio library and the opening videos are on the server and play.

## The short version, in plain words

Think of opening a new school. There are two different first days. **Sign-up day** is when each of the six makes their character on their own (induction, Gate A below). **The first lesson** is when everyone plays Episode One together (Gate B). Sign-up day is nearly ready. The first lesson is a long way off.

What I think needs doing, in this order:

1. **You read the six new questions** (A-1). They are the page for the players, in my wording, so nothing goes on the server until you say they are right. While you are there, decide whether the page should say that an AI helps prepare the game (A-11). At the moment it says only "your GM reads your answers", and the readers are you and me.
2. **You decide about the long joke contract** (A-2). It is nearly 57,000 words and switched off. Skim it and switch it on, or leave it off for now.
3. **I clear out the pretend stuff, with your yes** (A-4, A-8). There are six test characters in the project, probably some demo ones on the server (I cannot see the server from here), and the server is a little behind my work. One warning for me: the reset has an option that deletes every character made through the form, so it is only ever used before the real six sign up.
4. **You make six player accounts** and send each person a way in (A-5). Nothing is written down for them yet.
5. **Two snags to settle** (A-6, A-7). Someone logged in as GM, which means you, has to be online at the moment a player presses the final button, or their character is not made. And players cannot upload their own picture unless you switch that on in Foundry, or they send the picture to you instead.
6. **One practice run, both of us** (A-9). I play a pretend player on the real server, start to finish, then delete them. So far it has only been tested in a practice copy.
7. **Then open sign-ups**, in person or by post (A-10). Post is a good idea and fixes both snags, but it is not built. It needs a button for you to type in someone's answers so that the character belongs to them and not to you.

Episode One is the long road (B-1). One scene has been rebuilt the new way and is waiting for your read, one was signed off in September and has gone out of date, and the other ten are old drafts. My advice is not to wait for it. Open sign-ups first, and let what the players tell us shape the scenes as we rebuild them in order.

Before the first evening (section B): a backup of the server, a test with two computers connected, the opening video and the music checked on the live server, and a minute at the start saying "stop me if anything is too much".

The sections below are the detail behind each of those, with where each fact came from.

## Section C: the Discord server (optional, new 2026-10-01)

Your idea, 2026-10-01: a brand-new server for the campaign, populated through an official bot, as a living space where messages appear during the session. Tracked as `ideas/entries/discord-campaign-server.json` (status new) and GitHub #214. In the order it earns its keep:

- [ ] **C-1. The server and the bot.** **You:** create the server, then the Discord application and bot in Discord's developer portal, and keep the token in a local `.env` (already gitignored). The token never goes in chat or the repo.
- [ ] **C-2. The layout, from a script.** **Claude:** an idempotent setup script with a dry run that lists every channel, role, permission and pinned post before anything is made. It runs only after you have seen the list and said yes.
- [ ] **C-3. One-way drops from the session.** **Claude:** the Foundry module posts an in-world artefact (a message, a news bulletin, an order, a handout) at the moment a scene reveals it, using the same "told" rule as the canon (D048), through a GM-side relay so no token reaches a player's browser.
- [ ] **C-4. Two-way, living (after launch).** NPCs that answer, a Watcher that speaks. Needs a process that stays running, a model API key, hosting and a running cost, and it overlaps the campaign's own theme of surveillance, so the players must know and opt in before any bot reads their messages, and it uses only the fiction. Deferred.

Two rules for all of it: GM-only material never goes into Discord (the history is permanent and searchable), and a message is sent on your behalf only after you have seen it.
