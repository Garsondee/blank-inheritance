# reviews/qc/

The QC bot's reports, and what Ingram decided about each proposal in them. The design is
[design/qc-bot.md](../../design/qc-bot.md); the bot's own briefing is [tools/qc-bot/PROTOCOL.md](../../tools/qc-bot/PROTOCOL.md).

| Path | What it is | Written by |
|---|---|---|
| `reports/<scene>/<date>-<n>.json` | One review of one scene: how it works, up to eight proposals (each with its patch), the people check, chores, what was left alone. **The source.** | the bot |
| `reports/<scene>/<date>-<n>.md` | The same report as Markdown, for reading on GitHub. Generated by `qc render`; never edited. | the bot's tool |
| `decisions/<proposal id>.json` | Ingram's decision on one proposal: `accept`, `decline` or `discuss`, her reason **in her own words**, the option she chose for a question, and when it was applied. | `qc decide`, `qc decisions import`, `qc apply` |
| `focus.json` | Which episodes of the plan are in focus. Edit by hand to move the focus. | Ingram, Claude |
| `inbox.html` | The review page, built from the two folders above. Gitignored. | `qc page` |
| `published.json` | Where the review page is published, so it is updated in place. | Claude |

Everything is run through one command: `node tools/qc-bot/qc.mjs` (no arguments prints its usage).

The bot may write only into `reports/`. It never writes a decision. A decision is never edited, only replaced (the earlier
one stays in its `history`). `test/qc-bot/` holds the tests; `test/qc-bot/corpus.test.mjs` checks every file in these
folders against the real repo.
